# Imported native runtime and async API checkpoint

The isolated candidate now integrates a verified offline history import with the
actual native server. Application-history GET/POST, preparation Next permission
and local/hosted receipt reconciliation use scoped async transactions. Existing
preferences, professional facts and preparation ledger/reservation remain wired.
This checkpoint is an offline implementation and test result; it does not qualify
a Render/Turso deployment or authorize any live execution.

## Import reaches the runtime

`install-imported-history.mjs` accepts only a completed, independently verified
format-1 native snapshot and a new target path. It copies the complete database
image, checks the image hash and complete table/schema inventory, and runs the
real protected-history importer for every source account. All imported accounts
start stopped. It adds persisted native queue, ownership, preparation-resume,
attempt and reservation fences. Missing/incomplete history and invalid protected
identities fail closed. Imported protections and employer holds are included in
the preparation ledger and its private snapshot digest.

An `.INCOMPLETE` sidecar is created before copying. It remains after failure, and
`db.js` rejects that database before startup writes. Existing targets are never
overwritten or resumed automatically. Completion requires successful per-account
imports, source stability, quick-check and foreign-key verification. The marker
table cannot be changed through normal row writes. Trusted installers still have
DDL authority; database privilege separation remains unfinished.

The wrapper retains full native tables, including private account/profile data;
the inner history projection is still an allowlist. Only synthetic snapshots were
used here. No real credentials or private application data were read or copied.
Resume files are not copied and their stored paths are not rewritten by this
wrapper. It neither starts a process nor offers an account-activation flag.

## Runtime behavior

- Application-history import validates and upserts one account's records in one
  transaction. It blocks untouched duplicate jobs while preserving active and
  uncertain jobs, first evidence and later outcomes. The new path also preserves
  attempt-counter-only and event-only histories instead of relabeling those jobs.
  Bounded pages reject accounts exceeding the reviewed 20,000-job projection.
- Next permission reads ownership, account, focus, batch, campaign Stop and
  exclusion, profile and drafting consent, imported history and durable attempt
  evidence in one transaction. It grants no submission permission. Other local
  routes receive imported-history admission; their existing native checks remain.
- Every async native connection registers the native SQL guard functions. Native
  attempt insertion now upgrades an existing preparation journal entry to
  uncertain; deleting the mutable attempt row cannot restore preparation access.
- Receipt, outcome and evidence event commit together through the async adapter.
  The local endpoint and both hosted receipt callers await persistence. Full
  receipt text is validated before any write or replay, preserving first evidence
  and later outcomes. Lost acknowledgements remain uncertain without a write
  retry. Existing attributable receipts remain recordable during Stop/import
  holds and revoked preparation consent.
- The isolated SQL guard obtains default preparation timestamps from its own
  database clock. Explicit future timestamps still fail. This avoids intermittent
  false rejection when the client clock is slightly ahead of SQLite.

## Verification

`runtime-integrated-full-tests.log` records the final guarded `npm test` run:
644 native/HTTP regression tests, four UI checks and 221 async/guard/importer tests,
with zero test failures or skips. External fetches were blocked and background
tasks paused. Tests use temporary synthetic databases and loopback servers.

`checks/imported-runtime-api.test.js` exercises this actual local path:

1. Build a synthetic full source containing an uncertain attempt and fresh jobs;
   verify and import it into a new stopped native target.
2. Start the actual HTTP server on loopback and authenticate synthetic accounts.
3. Confirm stopped admission, then explicitly resume only the test fixture through
   test-owned SQL; an old uncertain attempt remains blocked while a fresh claim
   and Next permission succeed.
4. Import external history through HTTP; an active matching form cannot advance,
   an untouched matching job becomes duplicate, and reservation is blocked.
5. Exercise campaign Stop, revoked consent and cross-account/auth rejection.
6. Reconcile an attributable receipt for the old attempt while its account is
   stopped and preparation consent is revoked; preserve the source image hash.

No employer browser, provider, real account or worker was started. The hosted
receipt repository has native SQLite/local libSQL tests and its awaited production
call sites are checked; an actual hosted browser/remote deployment was not run.

## Remaining gates

Remote activation still unconditionally fails with
`database_remote_runtime_not_qualified`. Imported native fences depend on native
SQL functions and do not complete the SQL-only remote writer port. Queue/claim,
campaign scheduling, authentication/session, startup migrations and other callers
remain synchronous. Manual confirmation and the hosted manual-handoff fallback
remain unported; answer-library confirmation is still a native post-receipt helper.

An authorized, WAL-consistent production database and resume backup, verified
runtime paths/mounts, durable resume restoration, remote schema and privilege
qualification, all writer/authorization ports and deployment testing remain
required before cutover. Access and resource blockers remain unresolved; source
defaults are not runtime path evidence. No production stop, restart, upgrade,
configuration/origin change, installed-extension change, backup or cutover was
performed. The original checkout and persistent application history are unchanged.
